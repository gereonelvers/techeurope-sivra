# Buyer-Agent Vision Fine-Tune (Gemma 4 E2B, LoRA, Modal)

Fine-tune (intentionally overfit) a small **Gemma 4 vision** model so the buyer agent
maps a marketplace screenshot -> next UI action JSON. Tiny + fast -> runs many-in-parallel.

This directory is fully self-contained and isolated:
- its own venv at `vision_ft/.venv` (only `modal` + `python-dotenv` installed locally),
- all heavy deps (torch / unsloth / transformers / trl / peft) live in the **Modal image**, never locally,
- the source dataset under `../data/datasets/buyer/` is read **read-only**.

## File tree
```

  build_dataset.py       turns trajectories.jsonl -> (image, instruction -> action) examples

```

## Model + stack (verified)
- **Model id: `google/gemma-4-E2B-it`** — confirmed live on HF (HTTP 200), `any-to-any`
  multimodal, arch `Gemma4ForConditionalGeneration` (`model_type: gemma4`), needs
  `transformers >= 5.5`. Weights are bf16, **~10.2 GB** (5.1B params w/ embeddings, 2.3B effective).
  For our HF token this repo reports **`gated: False`** -> no license blocker hit.
- **Training stack: Unsloth `FastVisionModel` + TRL `SFTTrainer`** with
  `UnslothVisionDataCollator`. Pinned **`unsloth==2026.6.6`**, which resolves a clean
  set: `transformers 5.5.0`, `trl 0.24.0`, `peft 0.19.1`, `torch 2.10.0`.
  (A plain transformers+peft+TRL fallback path is also wired in `modal_app.py` in case
  Unsloth can't load gemma4 on a given day.)
- Note: Unsloth docs warn that **multimodal Gemma 4 loss sits around 13-15** and that is
  normal, so the smoke "loss finite + trending down" check accounts for high absolute loss.

## Dataset
Built directly from `../data/datasets/buyer/trajectories.jsonl` (no `sft.jsonl` exists).
One example per step:
- **input** = step screenshot (1280x800) + a FIXED system prompt (buyer-agent role +
  action schema) + the per-trajectory goal (`taskSpec` category/brand + site),
- **target** = that step's action JSON, e.g. `{"action":"click","x":590,"y":31}`.

Action vocab seen in data: `click` (x,y), `type` (text), `scroll` (dy), `done` (item_id).
(`navigate_back` is in the schema but unused in the current trajectories.)

The dataset is still being generated by another process; at last count it had **357
trajectories / ~4,900 steps** and growing (stats.json said 4,404; build_dataset reported 4,926).

## Smoke test (the current deliverable)
Self-contained: the GPU image bundles `build_dataset.py` + `smoke_data/`, so no volume
upload is needed to validate. The function:
1. loads `unsloth/gemma-4-E2B-it` (4-bit) on the GPU,
2. builds 16 image->action examples from the bundled slice,
3. runs ~15 LoRA steps with `UnslothVisionDataCollator`,
4. asserts weights load + the vision collator handles (image+text->action) with no shape
   errors + loss is finite, and prints the loss curve, GPU, and wall-time.

Run it:
```bash
cd vision_ft
set -a; source ../.env; set +a          # MODAL_TOKEN_ID / MODAL_TOKEN_SECRET
.venv/bin/modal run modal_app.py::smoke_test
```

## SMOKE TEST RESULT — PASSED (2026-06-13)
- Stack that worked: **Unsloth `FastVisionModel` + TRL `SFTTrainer`** (`unsloth 2026.6.6`,
  `transformers 5.5.0`, `trl 0.24.0`, `peft 0.19.1`, `torch 2.10.0`).
  Unsloth log: `Unsloth 2026.6.6: Fast Gemma4 patching. Transformers: 5.5.0` -> native gemma4 support.
- Model: `unsloth/gemma-4-E2B-it` (4-bit). 5.15B params, 29.86M trainable via LoRA (0.58%).
- GPU: **NVIDIA A100-SXM4-40GB**.
- 16 examples, 15 LoRA steps. Vision data collator handled (image+text->action) with NO shape errors.
- **Loss curve (finite, monotonic down): 7.84 -> 2.43**
  `[7.836, 7.77, 6.009, 4.865, 4.242, 3.831, 3.591, 3.18, 2.93, 2.791, 2.595, 2.545, 2.452, 2.423, 2.435]`
- Timing: image build 109s (cached now); weight download 46s (cached now); train 144s
  (15 steps, ~2.1s/step steady-state after first-step compile); GPU wall 237s.
- Rough cost of the smoke run: **~$0.14** (A100-40GB). No HF gating/license blocker:
  `google/gemma-4-E2B-it` reports `gated: False` for our token and weights pulled fine.

## Proposed FULL run (needs sign-off — DO NOT launch without approval)
1. Upload the dataset to the checkpoint volume (uses `Volume.batch_upload`, not an image build):
   ```bash
   .venv/bin/modal run modal_app.py::upload_dataset
   ```
2. Launch the real fine-tune (guarded by an explicit flag):
   ```bash
   .venv/bin/modal run modal_app.py::full_train --epochs 3 --i-have-signoff
   ```
- Dataset: ALL ~4,900 steps (one example per step).
- Epochs: 3 (intentional overfit; bump to 5 if eval grounding is weak).
- LoRA: r=16, alpha=16, dropout=0, `target_modules="all-linear"`, vision+language+attn+mlp
  all trainable; optim `adamw_8bit`, lr 2e-4, cosine, bs=1 x grad_accum=4.
- GPU: A100-80GB (more headroom for full-res 1280x800 images; 40GB also fits 4-bit).
- Output: LoRA adapter saved to volume `buyer-vision-ckpt:/adapter`.
